# Weather Dashboard

> 一个无需后端即可运行的玻璃拟态天气仪表板，支持全球城市与国家地区搜索、真实天气预报、动态天气背景、四语界面和五套主题色。

## 项目概览

Weather Dashboard 是一个轻量级静态前端应用。它先使用 Open-Meteo 地理编码服务把城市名转换为经纬度，再请求相应地点的当前天气、逐小时预报和七日预报，并把结果渲染为响应式玻璃拟态界面。[1] [2]

本项目不依赖 React、Vue、构建工具、后端服务或数据库。克隆后可用任意静态服务器运行，也可部署至 GitHub Pages、Netlify、Vercel 等静态托管平台。

| 项目属性 | 当前实现 |
| --- | --- |
| 前端技术 | HTML5、CSS3、Vanilla JavaScript |
| 天气数据 | Open-Meteo Forecast API |
| 地点检索 | Open-Meteo Geocoding API + 内置跨文字体系别名 |
| 图标 | Font Awesome 6.5.2 |
| 数据库 | 当前版本**不需要** |
| 默认语言与主题 | 中文、午夜蓝 |

## 功能

### 真实天气与预报

应用展示当前位置的温度、体感温度、湿度、风速、能见度、海平面气压与紫外线指数。预报区域显示从当前时刻开始的七个小时条目，以及连续七天的最高/最低温与降水量。接口请求采用 `timezone=auto`，因此页面会显示所选城市的当地时区。[1]

### 全球地点搜索与候选选择

输入至少两个字符即可检索全球城市、国家和地区。搜索会并行查询中文、英文、日语与韩语索引，并以稳定的地点 ID 合并结果；常见国际城市的中日韩别名会转换为标准查询，从而降低“同名本地地点”遮蔽全球主要城市的概率。对于重名地点，界面会显示最多五个候选项，并标注行政区及国家；用户选择候选项后，当前天气、预报、时区和天气氛围背景会一起刷新。[2]

| 输入示例 | 可返回的目标地点 |
| --- | --- |
| `东京`、`東京`、`도쿄`、`Tokyo` | 日本东京的候选项会优先出现 |
| `日本`、`Japan`、`일본` | 日本国家级地点候选项 |
| `Paris, France` | 可利用国家或一级行政区进一步缩小重名地点结果 |

### 本地名称与界面语言名称

选择地点后，天气主卡会同时显示该地点的**本地语言名称**与**当前界面语言名称**。主标题旁的徽标标明本地名称所使用的语言；下一行的名称会附带当前页面语言标记。例如，在韩语界面查看东京时，主标题显示日语本地名称“東京都”，下一行显示“도쿄 · 한국어”。地点的多语言名称由其稳定 ID 再次向 Open-Meteo 查询并缓存在浏览器会话中。[2]

### 四语界面

页面顶栏可在中文、English、日本語和한국어之间即时切换。语言切换会更新静态界面文案、天气描述、日期与时间格式、紫外线等级、预报卡片、加载/错误状态及可访问性标签。首次访问默认使用中文，之后会记住浏览器中的上次选择。

### 五套主题色

主题选择器提供以下颜色方案，所有方案均保留玻璃拟态层次与天气数据可读性。

| 主题 | 视觉定位 |
| --- | --- |
| 午夜蓝 | 冷静深蓝的默认主题，适合夜间阅读 |
| 深海青 | 青蓝渐变与清透高光 |
| 极光紫 | 紫蓝基调与浅色极光强调 |
| 落日暖橙 | 暖粉、紫红与琥珀色层次 |
| 森林绿 | 深绿、青绿与浅绿色强调 |

主题和语言偏好均保存在浏览器的 `localStorage` 中；同一浏览器下次访问会自动恢复。清除浏览器站点数据或使用无痕窗口后，会回到中文与午夜蓝默认设置。

### 与天气联动的动态背景

背景会根据 Open-Meteo 的 WMO 天气编码切换效果：晴天为微光粒子，多云为缓慢云层，雨天为细雨，雪天为飘雪，雾天为雾带，雷暴为细雨叠加低频闪电。为兼顾性能，手机端会减少粒子数量；如果操作系统开启“减少动态效果”，应用不会创建粒子层。[1]

## 快速开始

### 1. 克隆仓库

```bash
git clone https://github.com/amanmanlai-byte/Weather.git
cd Weather
```

### 2. 使用本地静态服务器运行

推荐通过本地服务器访问，而不是直接双击 HTML 文件：

```bash
python3 -m http.server 8000
```

随后打开 <http://localhost:8000>。也可以使用任意静态文件服务器，例如 `npx http-server`。

### 3. 使用方式

页面加载后默认查询伦敦。可使用中文、English、日本語或한국어输入城市、国家或地区名称并按 Enter；若返回多个地点，请从候选列表中选择准确的结果。主天气卡会依次呈现地点本地名称、其语言徽标、当前界面语言名称和页面语言标记。顶栏左侧为语言选择，旁边的调色板控件用于切换主题色。

## API 与数据流

```text
中英日韩地点输入
  → Open-Meteo Geocoding API（四种语言索引并行查询）
  → 内置国际城市/国家别名兜底与按地点 ID 的名称解析
  → Open-Meteo Forecast API（返回 current / hourly / daily 数据）
  → 前端本地化格式化与双名称渲染
  → 玻璃拟态天气界面与动态背景
```

Forecast API 支持按经纬度请求当前、小时和日级变量，地理编码 API 支持按地点名称返回匹配地点及其经纬度，并可通过地点 ID 请求本地化名称。[1] [2] 本项目会在浏览器会话中缓存地点天气、地点本地化详情与已解析的别名，以避免重复查询。

## 需要数据库吗？

**当前版本不需要数据库。** 这里的“数据”来自实时天气 API，应用没有用户账号、跨设备同步、服务器端写入或需要长期保存的业务记录。语言和主题偏好仅使用浏览器 `localStorage` 保存，属于单个浏览器本地设置，不是数据库。

| 需求 | 是否需要数据库 | 合理方案 |
| --- | --- | --- |
| 查询公开天气、切换语言和主题 | 否 | 当前静态前端 + Open-Meteo 即可 |
| 在同一浏览器记住主题/语言 | 否 | `localStorage` |
| 登录后跨设备保存常用城市 | 是 | 后端 API + PostgreSQL/MySQL 等数据库 |
| 保存天气提醒、订阅与推送记录 | 是 | 数据库 + 后端任务/通知服务 |
| 多用户共享城市清单或协作 | 是 | 用户认证、后端 API 和数据库 |
| 统计访问量 | 视需求而定 | 优先使用隐私友好的分析服务；自建统计才需要数据库 |

如果未来增加账号、收藏、提醒或推送功能，建议把浏览器直连天气 API保留为读取层，并增加后端作为认证、权限校验、数据持久化和定时任务入口。由于当前 Open-Meteo 调用不使用私密 API 密钥，静态托管已足够；接入任何私密第三方密钥时，应移到后端环境变量中，不能写入前端代码。

## 部署建议

项目可部署为纯静态网站。部署前应确认手机端布局、城市候选选择、弱网或接口失败提示、多语言切换、主题恢复，以及“减少动态效果”偏好均符合预期。可先创建预览环境供测试，再将已验收的版本发布到正式地址。

## 故障排查

| 现象 | 排查方式 |
| --- | --- |
| 未找到城市 | 尝试补充国家或地区，例如 `Paris, France` |
| 天气请求失败 | 检查网络连接，并稍后重试 Open-Meteo 服务 |
| 主题/语言未恢复 | 检查浏览器是否清除了站点数据或正使用无痕模式 |
| 动态背景未出现 | 检查操作系统是否开启“减少动态效果” |
| 样式未更新 | 强制刷新浏览器缓存，或重新启动本地静态服务器 |
